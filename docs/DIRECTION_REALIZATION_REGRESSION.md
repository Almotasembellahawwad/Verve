# Selected opening realization: first paired regression

## Reproduced gap

Four fixed briefs are compiled in two opening directions each, keeping their experience model, source facts, asset availability and file budget constant. On the pre-fix compiler, two pairs collapsed to identical opening genes:

- Carbon workbench: `task-first` and `canvas-first` both produced `rail-canvas` with the same seven genes.
- Arabic reservation: `question-first` and `story-first` both produced the same `split-stage` genes.

Architecture and Cairo print did not collapse in this fixture set. This is **two of four controlled compiler pairs**, not a measured failure rate across real provider runs or rendered websites.

## Cause and change

The narrative builder used opening mode to choose a scene role and as part of a deterministic seed. Composition selection then optimized generic scene shape, medium, model affinity and within-page diversity; it did not consume the selected opening intent as a preference. Distinct choices could therefore retain exactly the same composition.

The compiler now passes the selected opening mode to composition selection. For the primary opening only, multiple ranked spatial alternatives express that intent while retaining scene/content fit and deterministic tie-breaking. These are soft preferences, not fixed page templates or prohibited styles. Later scenes retain their existing fitness/maximin selection. Legacy callers without an opening mode retain the original algorithm. Route budgets, source facts, color/type assignment, asset rules, first-viewport tasks and model-call budgets are unchanged.

## Reproduce

Run `npx tsx --test tests/direction-opening-realization.test.ts`, or the full `npm test` suite. The test compiles eight contracts, checks valid schemas, non-identical opening genes within each pair, identical source facts/evidence, single-page intent, Fast's eight-file ceiling, reproducibility and existing local composition diversity requirements.

An additional selector-level check holds a neutral orientation scene and seed identical while changing only opening intent, so a different seed cannot account for the result. A separate check allows different content shapes to choose different structures for the same opening mode: content fit can still outweigh the soft preference. Not every pair of opening modes is guaranteed to produce different genes on every scene. Optional legacy callers remain reproducible without inventing an opening-intent claim; later scenes do not receive that claim.

The architecture fixture deliberately supplies no images and makes **no asset-delivery or launch-readiness claim**. Arabic compiler coverage does not substitute for RTL browser checks.

## What remains unproved

This regression fixes loss of intent **before code generation**. It does not prove the model follows the composition, that the final DOM matches it, that screenshots are beautiful, or that visitors prefer one direction. No new creativity score or paid model call is added. The public examples remain curated examples, not outputs from this regression.

The next checkpoint is the same four-brief/two-direction comparison on eight complete, consented engine runs, with actual supplied/licensed media. Capture the complete source/asset receipts, existing realization axes, screenshots at 360/768/1440 and explicit primary-task tests. Record collapsed composition, typography, media and state failures in the engine; do not hand-polish showcase code and attribute the result to generation. Live quality/cost/latency evidence must be separate from these offline compiler tests.
